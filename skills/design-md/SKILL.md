# /design-md

프로젝트의 디자인 언어를 `DESIGN.md` 한 파일로 고정한다. AI가 시안 없는 화면을 만들 때
기본값으로 돌아가는 것을 막는 게 목적이다.

⚠ **이 스킬의 유일한 규칙: 관측한 것만 적는다.** 좋아 보이는 디자인 원칙을 창작해 넣지 마라 —
그 순간 이 파일은 "또 하나의 남의 스타일 가이드"가 되고, 사람이 다시 고치는 루프가 그대로 남는다.
모르는 항목은 지어내지 말고 `## Known Gaps`에 적는다.

## 1. 근거 수집 — 이 순서대로

**(a) git 히스토리가 가장 강한 근거다.** 사람이 AI 결과물을 무엇으로 바꿨는지가 그대로 남아 있다.

```bash
git log --oneline --since="6 months ago" -i \
  --grep="디자인\|스타일\|톤\|통일\|정렬\|여백\|폰트\|간격\|design\|style" -- <앱경로>
```

같은 성격의 커밋이 여러 개면 그게 **반복 수정**이고, 곧 `Don't` 항목이다. diff에서
`className`/`class` 토큰을 뽑아 **추가된 것 vs 걷어낸 것**을 집계한다. 여러 커밋에 걸쳐
반복되는 토큰만 규칙으로 승격한다 — 한 커밋에만 있으면 그 화면 사정일 수 있다.

**(b) 현재 코드의 실사용 빈도.** 무엇이 실제로 쓰이는지가 무엇이 정의됐는지보다 중요하다.
토큰 정의 파일(`globals.css`·`tailwind.config`·`theme`)과 **실제 컴포넌트에서 쓰이는 클래스**를
따로 세서 비교한다. 정의됐지만 안 쓰이는 토큰은 디자인 언어가 아니다.

**(c) 기준이 되는 화면.** 대부분 랜딩·홈처럼 "가장 공들인 화면"이 기준이다. 어느 화면에 맞춰
나머지를 통일해 왔는지 커밋 메시지에서 찾고, 그 화면 코드를 직접 읽는다.

**(d) Figma MCP가 연결돼 있으면** `get_variable_defs`로 토큰을, `get_libraries`로 컴포넌트를
받아 (b)와 대조한다. 없으면 없는 대로 진행하고 `Known Gaps`에 적는다.

## 2. 쓴다

[DESIGN.md 규약](https://github.com/VoltAgent/awesome-design-md) 형식을 따른다:

```
## Overview          한 문단 — 이 제품이 어떤 인상이어야 하는가
## Colors            역할별. "무슨 색"만이 아니라 **위계를 무엇으로 만드는지**
## Typography        폰트 · 크기 스케일 · weight · letter-spacing · 숫자 처리
## Layout            여백 스케일 · 그리드 · 여백 철학
## Shapes            border-radius 스케일 · 테두리
## Components        버튼 · 카드/행 · 폼 · 배지 — 실제 쓰이는 아키타입
## Do's and Don'ts   ★ 이 파일에서 제일 중요한 절
## Responsive        브레이크포인트 · 터치 타깃 · 접힘 전략
## Known Gaps        확인 못 한 것
```

**`Do's and Don'ts`가 핵심이다.** 나머지는 코드를 읽으면 알 수 있지만, `Don't`는 사람의
수정 이력에만 있다. 각 항목은 **금지 대상과 대체재를 같이** 적는다:

```markdown
### Don't
- 시맨틱 텍스트 토큰(`text-text-sub`·`muted`·`dim`)으로 위계를 만들지 마라.
  → 위계는 `text-white/60` · `/50` · `/40` 투명도로 만든다.
- hover에 배경색을 쓰지 마라. → `hover:opacity-80`
```

- **추상적인 문장 금지.** "일관성 있게" · "적절한 여백" 같은 건 아무것도 강제하지 못한다.
  실제 클래스명·수치·토큰명으로 적는다.
- **근거 없는 항목 금지.** 각 규칙 옆에 어디서 관측했는지(커밋 해시·파일 경로)를 남기면
  나중에 사람이 검증할 수 있다.

## 3. 확인받는다

**초안을 보여주고 디자이너/사용자에게 확인받는다.** 이 파일은 앞으로 만들어질 모든 화면을
구속하므로 틀린 줄 하나가 오래 간다. 특히:

- 관측 근거가 약한 항목(커밋 1개에서만 나온 것)은 **표시해서** 물어본다.
- `Known Gaps`를 같이 보여준다 — 사람이 그 자리를 채워줄 수 있다.

## 4. 둘 곳

- 모노레포면 **앱마다** 둔다(`user/DESIGN.md`, `admin/DESIGN.md`) — 도메인마다 스타일이
  다른 게 정상이고, 하나로 합치면 둘 다 틀린다.
- 만든 뒤 그 앱의 `AGENTS.md`(또는 `CLAUDE.md`)에 **"UI 작업 전 `DESIGN.md`를 읽는다"** 한 줄을
  남긴다. 파일만 두면 안 읽힌다.

## 안 하는 것

- ❌ 남의 브랜드 DESIGN.md를 복사해 오지 않는다. 결과물이 그 브랜드처럼 되고, 여전히
  이 팀이 원하는 게 아니라서 사람이 또 고친다.
- ❌ 디자인을 **개선**하지 않는다. 이 스킬은 지금의 디자인 언어를 **기록**한다. 개선 제안은
  따로, 사람이 요청할 때.
